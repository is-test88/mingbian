# 明辨

## 方案推演与成事之法

> 《礼记·中庸》曰：“博学之，审问之，慎思之，明辨之，笃行之。”
>
> **大处明其所往，小处辨其所行；事理既通，而后笃行。**

**明辨，是一位陪你把事情真正想清楚的方案推演伙伴。**

很多方案并不缺内容，也不缺想法。真正的问题是：作者脑中已经补全的部分，并没有被写进方案；看似一致的目标，到了执行时却各有理解；一句“后续再细化”，往往藏着责任、规则、异常和验收上的关键分叉。

明辨不急着替用户写答案，也不会抛出一长串问题。它会先读尽材料、查实能够自行核实的事实，再找出真正会改变方向、路径、责任、风险、执行方式或验收结果的关键事项，一次辨明一件，并给出明确判断。随着用户每一次作答，后续推演都会重新计算，直到这件事不仅“听起来合理”，而且能够被执行、被交接、被验证。

最终，明辨会将共同想清楚的内容沉淀为一份 **《明辨录》**。

## 明辨为何而生

一份方案最常见的失误，不是完全错误，而是“尚未真正想清楚”：

- 说清了要做什么，却没说清为什么值得做、最终要改变什么；
- 方向似乎正确，却缺少动作通向结果的可信机制；
- 范围、优先级、资源和责任边界没有真正锁定；
- 执行细节留待以后，导致不同团队各自补全、反复返工；
- 只设计正常路径，没有想过缺失、冲突、超时、失败和人工接管；
- 能证明事情“做过”，却无法判断是否“做成”。

明辨的价值，不在于问得多，而在于让每一个会影响成败的关键点，都经过查实、判断、取舍和落定。

## 五步章法

明辨取法《中庸》五事，将其化为一套持续循环的推演方法：

| 章法 | 所行之事 |
|---|---|
| **博学** | 读尽来料，查实事实，不凭片段妄断 |
| **审问** | 由本及末，一次辨明一个真实取舍 |
| **慎思** | 推演因果、反事实、代价、异常与执行分歧 |
| **明辨** | 分清事实、决策、默认、假设、后议与阻断 |
| **笃行** | 形成《明辨录》，进入执行、交接与验收 |

这不是一套固定问卷。每得到一个新答案，明辨都会重新判断：哪些结论已经成立，哪些分支应当失效，哪些细节刚刚被解锁，下一件最值得辨明的事是什么。

## 六层辨题

明辨会沿着六层逐步下沉：

**辨本 → 辨路 → 辨界 → 辨序 → 辨法 → 辨成**

| 层次 | 要回答的问题 |
|---|---|
| **辨本** | 为什么做、为谁做、真正要改变什么 |
| **辨路** | 凭什么能成、为何选择这条路 |
| **辨界** | 做到哪里、哪些不能做、谁有权决定 |
| **辨序** | 先做什么、依赖什么、如何分阶段推进 |
| **辨法** | 谁在何时依据什么规则执行，异常如何处理 |
| **辨成** | 用什么证据判断做成、做偏、暂停或回退 |

明辨不会只盯“大问题”。一个看似很小的细节，只要会导致执行分歧、重复返工、责任悬空、风险失控或验收不一，就是必须想清楚的要事。

## 明辨带来的结果

完成一次明辨，不应只多出一份问题清单，而应得到四类确定性：

- **方向有据**：目标、对象、价值与成功证据彼此一致；
- **取舍有主**：关键决策已由正确的人作出，假设和风险被明确承认；
- **执行有法**：步骤、规则、责任、依赖、交接、例外和接管足以支撑真实落地；
- **成败有验**：知道何时算完成、谁来验收、什么情况下应调整或回退。

## 最终交付：《明辨录》

《明辨录》不是聊天摘要，而是一份行动底稿。它会根据实际内容覆盖：

- **所求之成**：问题、对象、目标、不做什么、成功证据；
- **所循之路**：核心机制、关键选择、阶段与关键路径；
- **已定之策**：已经锁定的重大取舍；
- **所守之界**：范围、约束、权限、责任、风险与护栏；
- **落地之法**：步骤、输入输出、依赖、默认值、例外与接管；
- **所据之实**：已核实事实、证据、显式假设及验证方式；
- **未尽之处**：后议事项、触发时点、阻断条件；
- **笃行**：下一步、责任人和近期验收点。

它应当让一个未参与对话的人，也能回答六个问题：为什么做、做什么、怎么做、谁来做、出了例外怎么办、凭什么算做成。

## 适用场景

明辨适合一切“准备认真推进、但仍需共同想透”的复杂事项，例如：

- 战略规划、组织变革与经营方案；
- 产品设计、需求定义与用户流程；
- 项目计划、实施路径与跨团队协作；
- 制度政策、业务流程与治理机制；
- 技术架构、系统建设与上线方案；
- AI Agent、自动化流程与人机分工；
- 汇报方案、决策材料与执行蓝图。

## 如何使用

```text
用明辨帮我把这份方案从大方向到执行细节真正想清楚，一次问我一个问题。
```

```text
先不要急着做。请用明辨逐项推演，给出你的判断，和我把关键取舍对齐后再执行。
```

```text
方向已经基本确定，请用明辨重点检查责任、规则、依赖、异常处理和验收方式。
```

```text
继续上次的明辨会话，先回读已定结论，再从当前最关键的未决事项接着推演。
```

## 明辨不做什么

- 不把能够自行查实的事实转问给用户；
- 不用固定清单替代对当前方案的真实思考；
- 不只谈宏观方向，也不沉迷无关紧要的枝节；
- 不把专业判断藏在“你觉得呢”之后；
- 不替用户接受重大风险、资源投入或责任；
- 不为了显得全面而无休止追问。

明辨遵循的停手原则是：

> **问至可行而止，不问至无事可问。**
