# 明辨

## 方案推演与成事之法

> 大处明其所往，小处辨其所行。问至可行，而后笃行。

**明辨是一位陪你把事情想清楚的方案推演伙伴。**

它不是替你润色几段文字，也不是抛出一长串问题。它先理解背景、查事实、给判断，再围绕真正会改变行动的关键问题与你讨论，把有价值的想法逐步变成可信、可接续的方案。

## 怎么用

在已经加载明辨 Skill 的对话环境里，直接说：

> **用明辨来跟我讨论一下 XXXXX。**

再大概说说这件事的背景、你的想法和目前最在意的限制。有方案或材料就一起提供；只有一个初步想法也可以，不需要填表或先写完整需求。

例如：

```text
用明辨来跟我讨论一下部门知识助手。
现在同事经常重复问流程问题，我想用 AI 减少这类重复答疑。
首期不准备改现有系统，希望先用已有资料验证这个方向。
```

明辨会给出初步判断，再一次讨论一件关键事项。材料充分时允许零问题结束；明确要求不再追问时，会直接形成带边界的阶段底稿。

## 3.2.0 的核心变化

- **按本次目标决定推演深度**：区分方向、试点、执行，不把方向讨论强行追问到生产细节，也不把执行方案停在原则层。
- **区分三类用户响应**：真实取舍、必要事实补充、具体授权确认采用不同门槛；“至少两个合理答案”只约束取舍题。
- **每答一问都更新方案**：上游变化后重新检查受影响的路径、责任与验收，不沿静态问题清单机械往下问。
- **能查的先查，能默认的透明默认**：不把检索、计算或低风险可逆细节转嫁给用户。
- **停止条件更准确**：用“方向就绪 / 试点就绪 / 执行就绪 / 尚未就绪”表达本阶段成熟度，不用问题数量证明专业。
- **《明辨录》改为灵活交付**：结论前置，只写有内容的部分，分清已定、建议、默认、假设、后议和阻断。

## 会得到什么

最终形成一份 **《明辨录》**，不是按问答顺序抄下来的纪要，而是按目标、路径、取舍、落地、依据与下一步重新整理的方案底稿。

方向讨论时，把方向与验证路径辨清；准备试点时，把范围、责任、护栏与验证辨清；准备交付执行时，进一步把流程、输入输出、交接、异常与验收补齐。没有达到执行条件的内容，不会被包装成“可直接落地”。

## 明辨怎样工作

文化骨架仍然是 **博学、审问、慎思、明辨、笃行**；推演视角仍然是 **辨本、辨路、辨界、辨序、辨法、辨成**。

这些用于判断，不是给用户逐项填写的问卷。用户的注意力主要用于真实取舍；能够查的由明辨去查；可逆、低风险的细节给透明默认；继续讨论不如取得证据时，设计有边界的验证。

## 可选：明辨簿

跨会话恢复、复杂依赖或审计留痕时，可继续使用 `scripts/mingbian_session.py`。**普通讨论不依赖 Python，也不要求使用状态脚本。**

本次 3.2.0 GitHub 提交优先升级推演规则与交互体验；明辨簿仍保持仓库原有 schema 2 协议与实现，避免在未完整提交、未完整回归的情况下把持久化协议半升级。后续如升级状态协议，应将脚本、协议和测试作为一个整体提交。

## 维护验证
