# 明辨

## 方案推演与成事之法

> 大处明其所往，小处辨其所行。问至可行，而后笃行。

**明辨是一位陪你把事情想清楚的方案推演伙伴。**

它不是替你润色几段文字，也不是抛出一长串问题。它先理解背景、查事实、给判断，再围绕真正会改变行动的关键问题与你讨论，把有价值的想法逐步变成可信、可接续的方案。

## 怎么用

在已经加载明辨 Skill 的对话环境里，直接说：

> **用明辨来跟我讨论一下 XXXXX。**

再大概说说这件事的背景、你的想法和目前最在意的限制。有方案或材料就一起提供；只有一个初步想法也可以，不需要填表或先写完整需求。

例如：

```text
用明辨来跟我讨论一下部门知识助手。
现在同事经常重复问流程问题，我想用 AI 减少这类重复答疑。
首期不准备改现有系统，希望先用已有资料验证这个方向。
```

明辨会给出初步判断，再一次讨论一件关键事项。你不需要预先告诉它应该问哪些问题。

也可以在过程中直接说：

```text
方向已经确定，接下来重点把责任、异常和验收讲清楚。
这轮先不追问了，把已有结论整理成一版方案，没定的单独标明。
先暂停，给我一份下次可以继续的检查点。
```

默认一轮一问；只有明确要求加速时，才合并最多三个互不依赖的问题。材料充分时，允许**零问题结束**。

## 会得到什么

最终形成一份 **《明辨录》**，不是按问答顺序抄下来的纪要，而是按目标、路径、取舍、落地、依据与下一步重新整理的方案底稿。

明辨会区分“已经定了什么”“目前建议什么”“暂按什么做”“哪些还需要验证”，不会把你的倾向写成批准，也不会把假设写成事实。

深度随当前需要调整：讨论方向时，把方向与验证路径辨清；准备试点时，把范围、责任、护栏与验证辨清；准备交付执行时，进一步把流程、输入输出、交接、异常与验收补齐。没有达到执行条件的内容，不会被包装成“可直接落地”。

## 明辨怎样工作

文化骨架仍然是 **博学、审问、慎思、明辨、笃行**；推演视角仍然是 **辨本、辨路、辨界、辨序、辨法、辨成**。

这些用于判断，不是给用户逐项填写的问卷。每次回答都会改变后续推演：已失效的问题不再继续；上游变了，受影响的下游要重审；无关的分支不会一起停摆。

用户的注意力主要用于真实取舍。能够查的由明辨去查；可逆、低风险的细节给透明默认；继续讨论不如取得证据时，设计有边界的验证。只有确实无法自查的信息，才向用户补充询问。

## 安装与更新

将完整的 `mingbian/` 目录放在你正在使用的 Agent 所支持的 Skill 目录中；具体目录和加载方式以该环境为准。更新已有安装时，先备份原目录，再用本包的 `mingbian/` 替换，按客户端要求重新加载。

**普通对话不需要安装 Python，也不需要运行命令。** Python 仅用于可选的本地明辨簿、维护验证和自动化测试。

没有文件或 Python 能力时，明辨仍可在当前对话中工作，并输出可复制的检查点；这不等于已经自动跨会话保存。

### 旧版明辨簿

3.2.0 的状态协议为 **schema 3**。3.1.0 的 schema 2 文件不会被静默改写；先 `status`，需要继续写入时再显式 `migrate`。迁移会创建不覆盖旧备份的副本，并保留旧结论供核对。

**普通用户没有使用过状态脚本，就无需迁移。** 不要为了更新 Skill 而新建或迁移不存在的会话。

详见 [状态协议](references/session-state.md)。

## 维护验证

Python 3.10 或更新版本；脚本只使用标准库。安装包不包含任何线上凭据，也不调用外部服务。

```bash
python3 -m unittest discover -s scripts -p 'test_*.py' -v
python3 scripts/validate_skill.py
```

代码测试、格式检查、模型行为是三层不同的验证。前两者通过，不等于模型在所有对话里都能正确提问；真实行为回归见 [验成规](references/evaluation.md)。

├── references/                    # 深入协议、示例、交付模板、状态与评估
