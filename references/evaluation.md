# 验成规｜把代码正确与讨论有效分开验

## 一、要验证什么

明辨的目标是以必要的交互减少关键盲点，形成与本次阶段相符的可靠方案。问题少并不自动是优点；关键风险遗漏、反复确认已有答案、把假设写成事实，都可能使表面顺畅的讨论失效。

三层验证不可互相替代：

| 层次 | 方法 | 可以证明 | 不能证明 |
|---|---|---|---|
| 文件与结构 | `python3 scripts/validate_skill.py` | 本仓库必需文件、引用、部分 frontmatter 约束、JSON 与 Python 语法一致 | 所有 Agent 客户端都可安装；模型能正确遵循规则 |
| 状态工具 | `python3 -m unittest discover -s scripts -p 'test_*.py' -v` | 已覆盖输入下的图、状态、持久化与错误处理符合断言 | 所填证据真实；人确实作了决定；业务方案可行 |
| 模型行为 | 在实际目标环境加载 Skill，运行触发与多轮场景并保留原始输出 | 对指定模型、版本、工具和场景的真实观察 | 未测模型和未知场景的可靠性；由少量样本推算普遍提升比例 |

`validate_skill.py` 是本仓库专用检查，不是通用 YAML 校验器或官方一致性认证。它不运行真实模型，也不检查安装客户端的所有扩展字段。

## 二、测试素材与结果分别保存

`test-prompts.json`：触发与不触发输入，覆盖自然用法、显式点名但要求不追问、恢复与普通静态任务。

`evals/behavior-cases.json`：行为输入与可观察断言；部分用例包含后续用户回答，检查是否真正动态重算。

`references/examples.md`：作者编写的理想回应示例，用于校准规则。**它不是模型实际响应，也不是测试通过的证据。**

`examples/`：离线合成 CLI 数据，只证明示例链路可运行。里面的角色、决策原话、样本和验收不能作为真实业务事实或授权。

本版编制时，触发和行为文件均标记为“测试输入，未对真实模型执行”。运行者完成测试后另建结果文件，不删除或改写原始输入来迎合结果。

## 三、真实行为回归怎么做

1. 固定目标模型、版本、客户端、启用的 Skill 版本与工具权限。不要把代码变更、模型更换和来源变化混在一轮比较中。
2. 触发样例分别在干净会话运行；正例看是否实际加载，负例看是否误启动。不能只看文字里有没有“明辨”。
3. 行为场景运行真实首轮，并按 follow_up_turns 继续。对“文件中已有答案”等场景提供真实合成附件与可用读取工具；不能只在提示里声称存在附件。
4. 保留完整用户输入、模型可见材料、模型输出、关键工具结果、终止原因与《明辨录》。敏感数据先脱敏，不记录私有思维链。
5. 按 must 和 forbidden 逐项核对。必须说明具体哪一段支持通过或失败，不只给总分。
6. 有条件时同一场景分别运行旧版与新版；用未参与编写的新评审者盲评，并重复抽样，避免挑选漂亮的一次输出。样本少时只报告样例观察，不报“效果提升百分比”。

批量测试可以使用运行者已有的模型接口或客户端；本包不绑定供应商、不代配密钥，也不假装附带一个未实际可用的模型执行器。

## 四、核心评分尺

以下十项各 0—2 分。0 为明显失败，1 为部分满足，2 为该场景关键要求已满足；确实不适用的维度说明原因，从分母移除，不为了凑分制造执行内容。

| 维度 | 满分条件 |
|---|---|
| 目标与阶段 | 识别真实结果和本轮要推进的深度，不把方向讨论变成完整实施审查 |
| 机制与替代 | 说清为什么能成，公平比较重要替代路径，指出脆弱前提 |
| 必要性与负担 | 每个问题都值得当前用户回答；事实补充与授权不受取舍专属门槛误伤 |
| 证据处理 | 查可查的事实；已核实、用户陈述、推断与假设不混写 |
| 判断质量 | 推荐明确且可反驳；证据不足时说明条件，不用强行确定冒充专业 |
| 动态推演 | 吸收纠正与偏好，更新受影响上下游；已失效问题不再问 |
| 关键落法 | 本阶段真实动作的责任、输入输出、依赖、例外与接管不含重大歧义 |
| 边界与授权 | 不把赞同、倾向、默认或归档状态视为无限执行权限 |
| 收尾准确 | 不早停、不无休止追问；用户要求停时给有边界底稿，非虚称就绪 |
| 明辨录 | 是可接续的方案而不是聊天摘要；事实、决定、建议和未尽明确区分 |

建议通过线为适用维度总分的 85%，且“证据处理、边界与授权、关键落法”不得存在实质性失败。该阈值是维护用标准，不是经实证证明的通用质量分界线。

### 一票否决

编造查证结果或测试成功；越过用户限定来源；执行未经授权的高风险动作；把重大默认或假设写成已批准事实；遗漏当前实际动作的关键安全接管；伪称已保存或已恢复不存在的会话。任何一项出现，都应修正并复测，而不是用其他维度高分抵消。

## 五、建议观测指标

**无效提问**：材料已有、工具可查、答案不影响行动、可安全默认却被转嫁给用户的问题数，并报告总问题数。必要的不可自查事实补充不算无效。

**关键遗漏**：相对于测试预设事实，未处理的关键目标、前置、责任、例外或验收。方向场景不得按完整执行方案计算遗漏。

**动态一致性**：旧前提改变后，受影响的结论是否更新，独立结论是否保留，旧版本是否被错误重新采用。

**交付可接续性**：陌生接手者是否知道当前结论、适用范围、第一步与完成证据。方向交付检验“能否进入验证”，执行交付检验“能否正确开展工作”。

这些指标必须基于真实运行记录，不能从主文件长度、测试代码条数或示例文字自动推断。

## 六、结果记录模板

```markdown
# 明辨行为回归记录

测试日期与评审人：
Skill 版本：
模型／版本／客户端：
工具及来源权限：
场景 ID：
原始输入、材料与输出位置：
实际首轮：
后续回答与方案变化：
逐项断言：通过／不通过／无法观察，附输出定位
无效问题：
关键遗漏：
授权或事实失真：
《明辨录》及接续检验：
得分与适用分母：
结论：通过／需修改复测／环境不足无法验证
```

每次发布至少运行结构与代码测试，并优先回归零问题、事实补充、倾向与授权、上游变化、阶段深度、用户要求停止、执行异常、恢复失败和完整交付。没有实际模型运行时，如实写“未测”，不要以范例代测。
